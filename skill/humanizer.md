# Humanizer Skill — AI 文本 → MonoShow 口语化

## 1. 概述

本 Skill 用于把 AI 生成（或 AI 味重）的文本改写成与 MonoShow 博客一致的**口语化人类口吻**。核心思路：**先识别 AI 套路，再注入博客的真人痕迹**。

```
输入：AI 味文本 / 通用改写稿
  → 检测 AI 典型模式（§3）
  → 提取博客真人痕迹特征（§4）
  → 逐段重写（§5 工作流）
  → 校验清单确认（§6）
```

适用场景：

- `obsidian-to-hexo-publisher` 改写后仍偏机械
- 直接让 LLM 输出的初稿需要"去 AI 味"
- 翻译稿 / 编译稿的中文化
- 同义改写避免原创度风险

## 2. 触发条件

遇到以下场景激活本 Skill：

- 用户说"太 AI 味"、"机器味"、"套话"、"机器人味儿"
- 文本来自通用 LLM 输出但要走博客
- 翻译稿需要中文化去翻译腔
- 改写后与博客已有文章风格差距明显

## 3. AI 文本的常见问题模式

### 3.1 套话开头（必删）

| AI 套路 | 真人替代 |
|---|---|
| "在当今 XXX 时代" | 直接进入主题 |
| "随着 XXX 的快速发展" | "最近" / "这两天" / "这一年" |
| "本文将探讨 / 介绍 / 分析" | 删除，让首段直接进内容 |
| "众所周知"、"不言而喻" | 删除或用具体例子 |
| "近年来，XXX 已经成为..." | "这一波 XXX 里..." / "踩 XXX 的人都知道..." |

### 3.2 公式化结构（必拆）

| AI 套路 | 真人替代 |
|---|---|
| "首先...其次...再次...最后...总之" | 用具体过渡（"先说..."、"再看..."、"最后说说..."） |
| 每段都"主题句+展开+小结" | 中间段落允许没有明确主题句 |
| "综上所述" | 删除或改成"所以"、"说到底"、"回头看" |
| "由此可见" | 改成具体观察 |
| 排比句过密（"不仅...而且...更..."连用） | 拆成短句 |

### 3.3 抽象感叹（必改）

| AI 套路 | 真人替代 |
|---|---|
| "这无疑是一个巨大的挑战" | "这事儿确实麻烦" / "其实挺烦的" |
| "带来了深刻的启示" | 删除；或"这点值得记下来" |
| "值得我们深思" | "说到底..." / "想想也是..." |
| "标志着..." | 用具体事实描述 |
| "开启了...的新篇章" | "从这开始..." |

### 3.4 翻译腔（必中文化）

| AI 套路 | 中文真人写法 |
|---|---|
| 长定语堆叠（"基于 XXX 的、用于 XXX 的、支持 XXX 的..."） | 拆成两句 |
| 被动语态（"被认为"、"被视为"、"被广泛应用于"） | 主动句："XXX 是..." / "大家普遍用 XXX" |
| 形式主语（"It is important to..."） | "重要的是..." / "得说..." |
| 抽象名词当主语（"实施带来了效益"） | 具体主语（"做完之后..."） |
| 英文标点 + 空格（中英文混排） | 全角中文标点（，。！？） |

### 3.5 过度修饰（删 30%）

| AI 套路 | 处理 |
|---|---|
| 每段都有"重要"、"关键"、"核心"加粗 | 加粗只保留关键判断 |
| 过度引用（每段一个 `[1][2][3]`） | 末尾汇总引用即可 |
| "显然 / 明显 / 当然" | 大多可删 |
| 套话连接词（"此外"、"与此同时"、"不仅如此"） | 改用短句或具体动词 |

### 3.6 完美对仗（破坏掉）

AI 倾向写排比、对仗、四字成语连用。真人写作很少这样：

- **删一半**对仗句
- 用长短句交错代替排比
- 偶尔留一处修辞作"亮点"，其余拆掉

## 4. MonoShow 博客口语化口吻规范

参考现有文章：`hello-world.md`、`EDH-combo.md`、`js同步和异步.md`、`slam-rgbd.md`、`Webpack_1/2/3.md`、`vue-notes.md`。

### 4.1 人称与视角

| 维度 | 规范 |
|---|---|
| **第一人称** | 多数技术稿用"我"、"本文"；偶尔"我们" |
| **第三人称自指** | 反思 / 抒情类允许"Kevin"（参考 `hello-world.md`） |
| **第二人称** | 谨慎使用；适合对话场景（"咱们"、"你想想"） |
| **避免** | "笔者"、"本人"、"愚以为" |

### 4.2 句长节奏

- 段内**短句 1–2 行**，长句不超过 3 行
- 长短句交错：不要连续 3 句都是长句
- 一个段落最多 4–5 句
- 偶尔出现"插队短句"或自问自答（"为啥？"、"对，就这么简单。"）

### 4.3 具体性原则

把抽象陈述换成具体场景：

| 抽象写法 | 具体写法（真人版） |
|---|---|
| "性能提升显著" | "原来跑 12 秒，现在 3 秒" |
| "用户体验良好" | "拖动一下就加载完，不卡" |
| "具有诸多优势" | "对我来说，省了 N 个步骤" |
| "应用广泛" | "我在 XXX、YYY 项目里都用过" |
| "可以有效解决..." | "踩过这个坑的人都懂，XXX 直接搞定" |

### 4.4 情感与反思

允许出现：

- **个人观察**："我试过两种方案，第二种明显舒服"
- **轻度吐槽**："说到底还是 XXX 写得不够细"
- **犹豫 / 反问**："到底要不要拆？拆；不拆？也行"
- **故事性开场**："去年这时候我踩了一个坑..."
- **自嘲**："这事儿如果早知道，能少走半年弯路"

不允许：

- 学术论文腔
- 公文式总结
- 鸡汤式结尾

### 4.5 标点与排版

- **全角中文标点**：，。！？：；（）""''
- **破折号**用 ——（两个 em dash）
- **加粗**节制：每段最多一处；段落关键判断才加粗
- **不滥用 emoji**：博客正文不出现；可偶尔在段落开头用 1 个
- **代码块**必须带语言标签
- **列表**：用 `-` 或数字编号，不要 `*`
- **链接**：行内 `[文字](URL)`，不在文本里直接贴裸 URL

### 4.6 博客已有"口癖"（可复用）

从已有文章里提取的高频口癖，改写时可借用：

- "**说到底**..." → 引出本质判断
- "**这事儿**..." → 口语化主题引入
- "**踩坑**"、"**试过**"、"**用过**" → 经验型陈述
- "**回头看**" → 反思性回溯
- "**有一点**"、"**说白了**"、"**换句话说**" → 过渡转折
- "**先说 / 再看 / 最后**" → 比"首先/其次/最后"更口语化

## 5. 转换工作流

按以下步骤处理输入文本：

```
Step 1: 通读原文，标出 AI 套路位置（§3 的 6 类问题）
Step 2: 标出抽象 / 套话 / 排比密度最高的段落（优先处理）
Step 3: 对每个标记位置，按 §4 规范重写
        - 套话开头 → 直接进入主题
        - 公式化结构 → 拆短句、用具体过渡
        - 抽象感叹 → 替换为具体场景
        - 翻译腔 → 中文化改写
        - 过度修饰 → 删 30%
        - 完美对仗 → 保留 1 处作亮点，其余拆
Step 4: 通读一遍，找"还可以更自然"的位置，注入个人观察（§4.4）
Step 5: 跑 §6 校验清单
Step 6: 输出对照表（哪段改了什么、为什么）
```

### 5.1 改写粒度

| 输入类型 | 改写粒度 |
|---|---|
| 通用 LLM 输出 | 重写 60–80%（AI 痕迹通常很重） |
| 翻译稿 | 重写 40–60%（主要去翻译腔） |
| `obsidian-to-hexo-publisher` 改写稿 | 微调 20–30%（主要去掉残留 AI 句式） |
| 已有真人稿润色 | 微调 10–20%（仅修个别僵硬句） |

### 5.2 对照输出格式

改写后建议附对照表，便于用户校验：

```markdown
## Humanizer 改写对照

| 位置 | 原文 | 改后 | 原因 |
|---|---|---|---|
| §1 首段 | "在当今 AI 时代..." | "最近..." | 套话开头 |
| §2 第 3 句 | "具有显著优势" | "省了我一下午" | 抽象→具体 |
| §3 结尾 | "综上所述..." | "所以..." | 套话连接词 |
```

## 6. 校验清单

发布前必须全部勾选：

- [ ] 首段没有"在当今..."、"随着..."、"众所周知..."等套话
- [ ] 没有"笔者 / 本人 / 愚以为"等书面化自称
- [ ] 没有"首先 / 其次 / 再次 / 综上所述 / 由此可见"等公式连接
- [ ] 没有"这无疑 / 带来了深刻的启示 / 值得我们深思"等抽象感叹
- [ ] 加粗节制（每段不超过 1 处，整文不超过 5 处）
- [ ] 标点全角化（中文段落不出现半角 `,.;?!`）
- [ ] 至少出现 1 处具体场景（数字、时间、人名、项目名）
- [ ] 至少出现 1 处个人观察 / 反思 / 自嘲
- [ ] 长短句交错（不连续 3 句长句）
- [ ] 不滥用 emoji（正文 ≤ 1 个）
- [ ] 没有连续排比 / 对仗 / 四字成语连用（> 2 个）
- [ ] 末段不是鸡汤或官方总结

## 7. 与其他 Skill 的衔接

```
Obsidian 笔记
 → [obsidian-to-hexo-publisher] → 初稿（已按博客规范改写）
 → [本 Skill · humanizer] → 真人化终稿
 → [article-platform-publisher] → 小红书 / 公众号版本
```

**调用顺序**：先跑 `obsidian-to-hexo-publisher`（保证结构、front matter、图片、链接都对），再跑本 Skill（保证口吻）。两者不要并行——并行会导致结构与口吻冲突。
