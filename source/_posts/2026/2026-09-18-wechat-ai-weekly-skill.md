## 一、14 个常用 Skill：给 WorkBuddy 装 App

对多数普通用户来说，Skill 是离「用上 AI」最近的一层。它把「某个领域的专业流程」封装成可一键安装的模块，让非开发者也能把 AI 调教成特定岗位的能手。下面这张清单覆盖了从安全、联网到办公、浏览、音视频的常见场景。

### 1.1 核心理念

**Skill = 给 WorkBuddy 装 App**。Skill 本质是一套「工作流程说明书」——告诉 AI 一件事从专业角度的标准流程、注意事项、最终输出长什么样。和手机 App 一样，装一个 Skill，AI 就拥有该领域的专业能力。

### 1.2 14 个 Skill 清单

| 类别 | Skill | 一句话 |
|---|---|---|
| 安全 | skill-scanner | 安装前做安全审查（Skill 脚本可能含恶意代码！） |
| 联网 | web-search | 接实时搜索 API，绕过训练截止日期 |
| 发现 | find-skills | 按自然语言描述找匹配的 Skill（官方市场 + SkillHub + GitHub） |
| 创建 | skill-creator | 创建新 Skill 的完整指南和模板 |
| 自进化 | self-improvement | 失败时自动记录上下文，下次同类任务前「复习」 |
| 格式转换 | markitdown | PDF/Word/PPT/Excel → Markdown，降低 Token 消耗 |
| 办公 4 件套 | pdf / docx / pptx / xlsx | 独立 Skill，分别对应四种办公文档处理 |
| 云端办公 | tencent-docs | 腾讯文档全套（建/读/编辑/剪藏/上传） |
| 浏览器 | agent-browser | 像真人一样操作浏览器（打开/填写/点击/截图/抓取） |
| 视频下载 | yt-dlp-downloader | B 站、抖音、YouTube 链接一键下载 |
| 语音转文字 | local-whisper | 本地 Whisper，敏感内容不上云 |

### 1.3 安装三原则

1. **优先官方推荐 → SkillHub → 自己从 GitHub 装**
2. **同类型别装多个**，AI 会陷入选择困难甚至串用
3. **可关闭可卸载**：关闭=暂停但保留，卸载=彻底移除

适合所有人：开发者、运营、销售、行政，AI 装上 Skill 就是该领域的专家。

## 二、千问 Skill 开放平台：面向履约时代的 Agent Runtime

如果说上一节是「用户视角怎么装 Skill」，这一节就是「平台视角怎么把 Skill 做成基础设施」。千问的思路不是再做一个插件市场，而是把 Skill 升级成能真正替用户把事办完的运行单元。

### 2.1 核心理念与五大技术架构

**千问 Skill 不是传统插件列表**，而是「可被模型理解 / 系统调度 / 沙箱约束 / 多端渲染 / 完成履约闭环」的服务单元。让 Agent 从「会对话」走向「可托付」。

| 模块 | 关键能力 |
|---|---|
| **算法 + 工程结合** | 模型理解 + 领域召回 + 实时信息校准 + 工具调用四步决策 |
| **审核 + 沙箱** | 上架前自动校验、运行时独立沙箱、高危操作确认卡片、关键结果留痕 |
| **云端 Harness** | 长程任务托管到云端（锁屏/断网/换设备可续），挂起-确认-恢复 |
| **Schema-Driven Native UI** | 模型输出结构化 UI Schema → 端侧渲染 Native UI（手机/PC/AI 眼镜自适应） |
| **跨 Skill 调度** | 复杂任务（出差/租房）= 目标拆解 + 串并行调度 + 进度控制 + 履约闭环 |

接入终端：手机、PC、AI 眼镜三类统一接入；已上线 400+ AI 办事能力；首批伙伴含菜鸟、夸克网盘、夸克扫描王、物流、房产、本地生活、理财、汽车等。平台地址 [open.qianwen.com/home](https://open.qianwen.com/home)。

### 2.2 传统插件 vs 千问 Skill

| 维度 | 传统插件 | 千问 Skill |
|---|---|---|
| 能力发现 | 静态描述 + 人工配置 | 模型理解 + 领域召回 + 实时校准 |
| 执行方式 | 会话内同步（易中断） | 云端 Harness 托管（挂起+续跑） |
| 安全边界 | 凭证权限分散 | 审核/沙箱/高危确认/留痕 |
| 交互形态 | 文本/Markdown | Schema 驱动 Native UI |
| 业务闭环 | 建议/跳转 | 账号 + AI 支付 + 订单 + 通知 |

## 三、知识库搭客户系统

Skill 解决「能力」问题，知识库解决「记忆」问题。这一节把二者结合：用 WorkBuddy 搭配知识库，把零散的客户沟通沉淀成一套可持续运转的客户系统，而不是每次都从零开始。

### 3.1 三层架构

**不要把 AI 当一次性工具，要把客户上下文沉淀成「客户系统」**。一次 AI 提效 → 完整客户生命周期管理。

```text
┌─ 第一层：客户总表（多维表格 / CRM）
│   → 解决「我现在应该关注谁」
│
├─ 第二层：一份客户一份档案（独立文件夹）
│   → 解决「这个客户过去发生过什么」
│
└─ 第三层：按客户类型建立工作空间
    → 解决「同类客户的共性知识」
```

### 3.2 第二层档案八类固定资料

| # | 类别 | 内容 |
|---|---|---|
| 01 | 客户基本信息 | 公司、联系人、决策链 |
| 02 | 沟通原始资料 | 录音转写、微信聊天、会议笔记 |
| 03 | 历次结构化记录 | 按固定模板整理的沟通记录 |
| 04 | 动态客户画像 | 从沟通中长出来的画像 |
| 05 | 需求、顾虑、异议 | 反复出现的问题 |
| 06 | 报价单 + 合作方案 | 报价与方案历史 |
| 07 | 成交内容 + 成交过程 | 决策参与人、关键节点 |
| 08 | 下一步跟进 / 服务 / 复购 | 持续动作 |

动态客户画像三原则：①客户事实 vs AI 推测必须明确区分；②每条结论必须有信息依据 + 日期；③【已确认】vs【待验证判断】必须标注。

### 3.3 三件不能交给 AI 自动决定的事

1. **客户意向 / 商机阶段**——必须销售判断
2. **价格 / 参数 / 合同条款 / 承诺**——必须人工核对
3. **资料权限**——录音/微信/合同涉及敏感信息，必须授权

落地路径：先选 5 个重点客户，建档案，跑两周；等目录、字段、跟进流程稳定后再固化成专属 Skill。

## 四、PPT 能力升级：一句话做出可上台版本

办公文档里最让人头疼的往往是 PPT——既要内容讲得通，又要视觉过得去。这一节的升级重点，是把「第一版就能上台」作为目标，而不是先堆十几页再返工。

### 4.1 五步工作流

**第一版就要接近「能上台」的标准**，而不是「十几页内容快出来」。解决三个问题：①材料乱怎么开始 ②内容能不能讲顺 ③哪里要改改哪里。

```text
1. 入口：直接说"帮我生成一份 PPT" 或点击顶部「幻灯片」
2. 输入：想法 / 文档 / 模板 / 参考页面（材料不必准备到"完整可用"）
3. 确认：信息不足时 AI 主动问，方向确认后生成内容
4. 生成：内容讲清楚 + 视觉风格统一 + 可继续编辑的 .pptx
5. 修改：哪里要改就改哪里，不满意单独改一页或自己动手
```

### 4.2 三大升级亮点

| 升级 | 旧版问题 | 新版解法 |
|---|---|---|
| 内容更顺 | 页面观点不连贯、没主线 | 先组织（问题线 + 页面职责）→ 再呈现 |
| 视觉更专业 | 配色乱、版式杂、不统一 | 按汇报场景选视觉方向（答辩/路演/科技各有风格） |
| 可继续编辑 | 改一行字整份重来 | 点选/框选元素 → 直接说怎么改 → 显示修改前后 |

### 4.3 模板支持

- **有固定模板**：连同模板一起交给 AI，保留主题色、字体层级、页面结构
- **只有喜欢的风格**：参考某份 PPT 的配色 / 字体层级 / 版式节奏
- **只有某一页好看**：明确告诉 AI 沿用哪类页面结构

适合任何人做汇报：工作汇报 / 课程答辩 / 路演提案 / 品牌策略。

## 五、AITutor 自进化架构：双智能体 + 知识本体

前面几节多是单点能力，这一节给出一套更完整的「AI 原生系统」范式：如何让内容产品不靠人工苦撑，也能持续进化。它的核心是把「知识本体经验」当作系统的一等公民。

### 5.1 双智能体拆分

**AI 内容产品都会死循环**：①前沿性不足（新知识滞后）②存量过时（旧内容没人回头看）③成本高昂（人工运维无法规模化）。AI 时代知识半衰期已压缩到「周」。

```text
       Hermes 通用引擎
       │
   ┌───┴───┐
   ▼       ▼
 增量进化  存量焕新
（新知识） （旧知识）
   │       │
   └───┬───┘
       ▼
   知识本体经验库
   （沉淀 · 复用 · 反哺）
```

为什么必须两个？一个智能体同时做「新知识生产」和「旧知识判定」，提示词互相污染、评估标准互相干扰，所以职责分离。

### 5.2 八步标准生产链路

```text
1. claim_topic          从 topic-agent 领取待写主题（无主题自动终止，不空转）
2-3. 搜索并过滤资料    ← 拉取经验（过滤）+ 公开素材 → 逐条过滤
4. 大模型写课件        ← 基于经验（写作）按 L1/L2/L3 级别选模板 → 逐章节生成
4.3-4.4 插画 + 音视频  逐章生图上传 OSS → 产出 video.md / audio.md
5. AI 评估             ← 基于经验（评估）按 0-100 标准化打分
6. 合并上报 submit     提交服务器返回 articleId
7. 人工审核            不通过 → 问题经验自动沉淀 → 回流至步骤 2-3
8. 上线                归入线上知识库
```

三大关键设计：①禁止人工手写正文——保证经验闭环不被污染；②课程级别决定提示词（L1/L2/L3 三套模板不能串）；③人工审核是核心进化触发点——三类批注（检索/生成/评估）反哺各自环节。

### 5.3 三个反问

任何 AI 原生系统都该问：

```text
① 我的系统，有没有地方在沉淀知识本体经验？
② 沉淀下来的经验，有没有被真正复用回执行链路？
③ 用户的每一次使用、每一次纠错，有没有让系统变得更强？
```

适合任何做 AI 内容产品 / 知识库 / Agent 系统的团队。
